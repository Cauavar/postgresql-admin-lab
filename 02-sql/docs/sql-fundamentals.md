# SQL Fundamentals

## Objective

This document records the SQL concepts and operations practiced during the PostgreSQL administration laboratory.

The focus is on understanding how SQL is used to define database structures, manipulate data, retrieve information, enforce data integrity, and work with sequences.

## DDL — Data Definition Language

DDL commands are used to create and modify database objects.

The main commands studied in the project include:

```sql
CREATE DATABASE
CREATE SCHEMA
CREATE TABLE
CREATE SEQUENCE
ALTER TABLE
ALTER SEQUENCE

These commands define the structure that will store and organize the data.

DML — Data Manipulation Language

DML commands manipulate the records stored in database tables.

The main commands used are:

INSERT
UPDATE
DELETE
INSERT

INSERT adds new records to a table.

Example:

INSERT INTO public.tb_product (name, price)
VALUES ('Keyboard', 110.00);
UPDATE

UPDATE modifies existing records.

Example:

UPDATE public.tb_product
SET price = 120.00
WHERE product_id = 1;

The WHERE clause is important because it determines which records will be modified.

DELETE

DELETE removes records from a table.

Example:

DELETE FROM public.tb_product
WHERE product_id = 1;

As with UPDATE, the WHERE clause should be used carefully to avoid modifying or removing unintended records.

SELECT

SELECT is used to retrieve data.

Basic example:

SELECT *
FROM public.tb_product;

Specific columns can also be selected:

SELECT product_id, name, price
FROM public.tb_product;
Filtering

The WHERE clause filters records according to a condition.

Example:

SELECT *
FROM public.tb_product
WHERE price >= 100;

Multiple conditions can be combined using operators such as:

AND
OR
NOT
Ordering

The ORDER BY clause controls the order of query results.

Example:

SELECT *
FROM public.tb_product
ORDER BY price DESC;

ASC orders values in ascending order.

DESC orders values in descending order.

Constraints

Constraints enforce rules on table data and help maintain data integrity.

The project uses:

PRIMARY KEY

Uniquely identifies each record.

CONSTRAINT products_pkey
PRIMARY KEY (product_id)
NOT NULL

Prevents a column from receiving NULL.

Example:

name VARCHAR(100) NOT NULL
CHECK

Ensures that inserted or updated values satisfy a condition.

Example:

CONSTRAINT products_price_positive
CHECK (price >= 0)

Another validation used by the project prevents empty product names:

CONSTRAINT products_name_not_null
CHECK (name <> '')
Sequences

A sequence is a PostgreSQL object that generates numeric values.

The project uses:

public.product_product_id_seq

The sequence is associated with:

public.tb_product.product_id

The column uses:

nextval('public.product_product_id_seq')

to obtain the next identifier.

This allows new records to receive automatically generated IDs.

Data Integrity

The combination of constraints and sequences helps protect the consistency of the database.

For example:

product_id
    |
    +---- generated by sequence
    |
    +---- PRIMARY KEY

while:

name
    |
    +---- NOT NULL
    |
    +---- cannot be empty

and:

price
    |
    +---- NOT NULL
    |
    +---- must be >= 0
